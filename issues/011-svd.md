# 011 — Generator SVD

**Status:** ✅ zrobione
**Zależy od:** 010
**Uwaga:** projekt niezależny — może powstać wcześniej jako osobne narzędzie

## Opis

**To jest rzecz, która realnie uzasadnia istnienie Klina** — nie metody
na strukturach.

CMSIS-SVD to XML publikowany przez producentów MCU: każde peryferium,
adres bazowy, każdy rejestr, każde pole bitowe, szerokość, offset, prawa
dostępu, wartość po resecie, oraz `<enumeratedValues>` z nazwanymi
wartościami. Cała wiedza potrzebna do wygenerowania typowanego dostępu
do sprzętu leży w jednym pliku.

Rust ma na to `svd2rust`. TinyGo ma `tools/gen-device-svd`.

## Cel

```
$peripherals_from_svd("STM32F411.svd")

RCC.AHB1ENR.GPIOAEN.set(1)
GPIOA.MODER.MODER5.write(.Output)   // enum z SVD, nie magiczna liczba
GPIOA.ODR.ODR5.toggle()
```

musi wyemitować dokładnie:

```c
*(volatile uint32_t*)0x40023830 |= (1u << 0);
*(volatile uint32_t*)0x40020000 =
    (*(volatile uint32_t*)0x40020000 & ~(3u << 10)) | (1u << 10);
*(volatile uint32_t*)0x40020014 ^= (1u << 5);
```

**Jeśli gdziekolwiek pojawia się wywołanie funkcji, którego nie ma
w wersji ręcznej — zasada nadrzędna złamana.**

## OSTRZEŻENIE: pliki SVD producentów są pełne błędów

Jakość plików od producentów jest kiepska, z rozbieżnościami między SVD,
dokumentacją i faktycznym sprzętem. Pliki ST nie są wyjątkiem.

TinyGo **nie używa** oryginalnych plików ST, tylko poprawionych przez
projekt `stm32-rs`. Generator `ecg` wykrył błędy w SVD od ST przez
asercje sprawdzające offsety.

**Pipeline:** oryginalne SVD ST → łatki stm32-rs → mój generator.
Gotowe czyste pliki: repo `tinygo-org/stm32-svd`.

To oszczędza tygodni debugowania sytuacji "kod poprawny, LED nie miga".

## Implementacja

Docelowo preprocesor kompilatora (w Darcie). Na prototyp można użyć
gotowego parsera:

- Python: `cmsis-svd` (posborne), `svdsuite`
- Go: wzorzec w TinyGo `tools/gen-device-svd` — ma rozwiązane klastry,
  podklastry, tablice rejestrów, `derivedFrom`

**Wziąć gotowy parser, napisać własny emitter.** Parsowanie SVD to nudne
80% pracy, ciekawe 20% to codegen.

## MVP

`bin/svd2klin.dart` czyta SVD i emituje lokalny nagłówek C oraz deklaracje
Klin. Obsługuje pola i rejestry `dim`, proste `derivedFrom` oraz syntetyczny
SysTick (`STK`) dla STM32F411, którego nie ma w źródłowym SVD. Ergonomiczne
API językowe pozostaje osobnym krokiem: [027](027-svd-ergonomic-api.md).
