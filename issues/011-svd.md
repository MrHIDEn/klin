# 011 — SVD generator

**Status:** ✅ done
**Depends on:** 010
**Note:** independent project — can be built earlier as a separate tool

## Description

**This is what really justifies Klin's existence** — not methods
on structs.

CMSIS-SVD is XML published by MCU vendors: every peripheral,
base address, every register, every bit field, width, offset, access
rights, reset value, plus `<enumeratedValues>` with named
values. All knowledge needed to generate typed hardware access
lives in one file.

Rust has `svd2rust` for this. TinyGo has `tools/gen-device-svd`.

## Goal

```
$peripherals_from_svd("STM32F411.svd")

RCC.AHB1ENR.GPIOAEN.set(1)
GPIOA.MODER.MODER5.write(.Output)   // enum from SVD, not magic number
GPIOA.ODR.ODR5.toggle()
```

must emit exactly:

```c
*(volatile uint32_t*)0x40023830 |= (1u << 0);
*(volatile uint32_t*)0x40020000 =
    (*(volatile uint32_t*)0x40020000 & ~(3u << 10)) | (1u << 10);
*(volatile uint32_t*)0x40020014 ^= (1u << 5);
```

**If a function call appears anywhere that is not
in the hand-written version — the prime rule is broken.**

## WARNING: vendor SVD files are full of errors

Quality of files from vendors is poor, with discrepancies between SVD,
documentation, and actual hardware. ST files are no exception.

TinyGo **does not use** original ST files, only corrected ones from
the `stm32-rs` project. The `ecg` generator found errors in ST SVD through
offset-checking assertions.

**Pipeline:** original ST SVD → stm32-rs patches → my generator.
Ready clean files: `tinygo-org/stm32-svd` repo.

This saves weeks of debugging "code correct, LED does not blink".

## Implementation

Eventually the compiler preprocessor (in Dart). For prototype you can use
an existing parser:

- Python: `cmsis-svd` (posborne), `svdsuite`
- Go: pattern in TinyGo `tools/gen-device-svd` — has clusters,
  subclusters, register arrays, `derivedFrom` solved

**Take a ready parser, write your own emitter.** Parsing SVD is boring
80% of the work; the interesting 20% is codegen.

## Completion criteria

- [x] typed GPIO access generated from SVD
- [x] blink example uses generated accessors; ARM test still compares
  ISR symbol when toolchain is available
- [x] named enums emitted as C definitions; Klin MVP passes their
  numeric values with a comment, because global constants are not yet supported

## MVP

`bin/svd2klin.dart` reads SVD and emits a local C header and Klin
declarations. Handles `dim` fields and registers, simple `derivedFrom`, and synthetic
SysTick (`STK`) for STM32F411 missing from source SVD. Ergonomic
language API remains a separate step: [027](027-svd-ergonomic-api.md).
